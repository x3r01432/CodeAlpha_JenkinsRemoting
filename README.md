# CodeAlpha_JenkinsRemoting

CodeAlpha DevOps Internship, **Task 2: Jenkins Remoting**. A Jenkins controller and two build agents in Docker Compose. The controller is configured entirely as code (JCasC), launches its agents over SSH using Jenkins Remoting, and a sample pipeline spreads its stages across the agents by label.

## Architecture
```
                 ┌────────────────────────────────────────────┐
 browser :8081 ─►│ controller  jenkins/jenkins:2.580.1-lts-jdk21│  executors = 0 (no builds here)
                 │  JCasC: users, nodes, creds, job            │
                 └──────────┬───────────────────────┬──────────┘
                SSH + Remoting (remoting.jar)   SSH + Remoting
                 ┌──────────▼──────────┐   ┌────────▼────────────┐
                 │ agent-debian        │   │ agent-alpine        │
                 │ ssh-agent:6.11.1-   │   │ ssh-agent:6.11.1-   │
                 │   jdk21 (glibc)     │   │   alpine-jdk21 (musl)│
                 │ labels: linux       │   │ labels: linux       │
                 │  linux-amd64 debian │   │  linux-amd64-alpine │
                 │                     │   │  alpine musl        │
                 └─────────────────────┘   └─────────────────────┘
```

| Path | Purpose |
|---|---|
| `controller/Dockerfile` | pinned controller image, installs plugins, bakes in JCasC + pipeline |
| `controller/plugins.txt` | **every** plugin (62, incl. dependencies) pinned to an exact version |
| `controller/casc/jenkins.yaml` | security realm, 0 controller executors, nodes, SSH credential, host-key pinning, job seed |
| `controller/jobs.groovy` | Job DSL seed that creates `multi-agent-demo` |
| `controller/pipelines/Jenkinsfile` | the label-routed pipeline |
| `agents/entrypoint-wrapper.sh` | installs the pre-generated host key + authorized key, then starts the stock agent sshd |
| `scripts/gen-secrets.sh` | generates SSH keys and admin password into `secrets/` and `.env` (both git-ignored) |
| `proof/` | real console output and agent launch logs |

### About "architecture/OS" labels (honest note)
Both agents run on the same x86_64 host, so the split is by **OS / C library** (Debian + glibc vs Alpine + musl), not by CPU. Labels `linux-amd64` and `linux-amd64-alpine` reflect that truthfully. To add a real `linux-arm64` agent, register QEMU (`docker run --privileged --rm tonistiigi/binfmt --install arm64`) and add a third service with `platform: linux/arm64` and the label `linux-arm64`, or connect a real ARM machine (e.g. Raspberry Pi) with the same SSH launcher block. That emulated agent was **not** run here.

## Security / node isolation
- **No builds on the controller**: `numExecutors: 0`, mode `EXCLUSIVE`; the built-in node shows 0 executors (`proof/nodes.json`).
- **Agents in EXCLUSIVE mode**: they only run jobs that ask for their labels.
- **Agent → controller security**: always on in this Jenkins release (it can no longer be turned off), so agents cannot read controller files or run controller commands.
- **Inbound TCP agent port disabled** (`slaveAgentPort: -1`); only the web UI port is published. Agents have no published ports.
- **SSH host keys pinned**: each agent gets a pre-generated host key; the controller uses *Manually provided key* verification, so a spoofed agent is refused (log: "SSH host key matched").
- **Secrets never committed**: private keys and the admin password are generated by `scripts/gen-secrets.sh` into `secrets/` and `.env` (git-ignored) and mounted read-only; JCasC reads them with `${readFile:...}` and `${JENKINS_ADMIN_PASSWORD}`.
- **Non-root builds**: steps run as user `jenkins` (console shows `user=jenkins`). sshd in the agent image runs as root, as the stock image requires.
- Login required (no anonymous read), CSRF protection on, signup off, pipeline runs in the Groovy sandbox, memory limits on every container.

## Run it
```bash
./scripts/gen-secrets.sh                  # once
docker compose up -d --build
# wait ~60 s, then open http://localhost:8081 (login from .env)
# Build "multi-agent-demo", or via CLI:
. ./.env; J=http://localhost:8081; A="$JENKINS_ADMIN_ID:$JENKINS_ADMIN_PASSWORD"
C=$(curl -s -c /tmp/cj -u $A $J/crumbIssuer/api/json | python3 -c 'import sys,json;d=json.load(sys.stdin);print(d["crumbRequestField"]+":"+d["crumb"])')
curl -s -b /tmp/cj -u $A -H "$C" -X POST $J/job/multi-agent-demo/build
curl -s -u $A $J/job/multi-agent-demo/lastBuild/consoleText
docker compose down -v                    # tear down
```
If agents stay offline with "Connect timed out", the host firewall is dropping traffic between Docker bridge networks; see Troubleshooting.

## Troubleshooting
- **Agents offline, "Connect timed out"**: check `docker compose exec controller bash -c '</dev/tcp/agent-debian/22'`. On hosts with leftover iptables-legacy rules the FORWARD policy may be DROP; allow bridge-to-bridge traffic: `sudo iptables -I DOCKER-USER -i br-+ -o br-+ -j ACCEPT`. (This was needed on the test machine.)
- **"Illegal base64 character a"** at boot: a host-key file has a trailing newline; rerun `gen-secrets.sh` (it writes them without one).
- **JCasC boot failure**: `docker compose logs controller | grep -A3 SEVERE` shows the bad YAML key.
- An `UnknownHostException: updates.jenkins.io` SEVERE line just means no internet for update checks; harmless.
